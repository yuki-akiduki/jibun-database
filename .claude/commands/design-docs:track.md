# AI駆動開発: タスク進捗管理

カレント設計書の進捗を確認・更新します。

## ステップ1: カレント設計書の取得

`.claude/.current-design-doc` を読み、設計書ディレクトリパスを取得する。

**ファイルが存在しない場合**:
```
❌ カレント設計書が見つかりません。

`/design-docs:plan` または `/design-docs:switch` を先に実行してください。
```

---

## ステップ2: tasks.md の読み込みと進捗表示

`tasks.md` を読み、以下の形式で表示:

```
📋 カレント設計書: {パス}

## 全体進捗

{進捗バー: [████████░░] 80% (4/5 Phase 完了)}

## Phase 別ステータス

| Phase | 状態 | 完了日 | タスク進捗 |
|-------|------|--------|----------|
| Phase 1: 型定義追加 | ✅ Done | 2026-04-08 | 3/3 |
| Phase 2: ライブラリ層 | ✅ Done | 2026-04-09 | 4/4 |
| Phase 3: UI コンポーネント | 🚧 In Progress | - | 2/4 |
| Phase 4: 統合 | 🔲 Pending | - | 0/3 |

## 現在の Phase: Phase 3 - UI コンポーネント

残りタスク:
- [ ] TagFilter.tsx 実装
- [ ] ActiveFilters.tsx 実装

完了タスク:
- [x] useTagFilter.ts 実装
- [x] TagBadge.tsx 実装
```

---

## ステップ3: アクションの提案

現在の進捗に応じて、次のアクションを提案:

### すべて未着手の場合
```
💡 まだ実装が始まっていません。

次のアクション:
- `/design-docs:start` で Phase 1 から開始
```

### 一部完了の場合
```
💡 現在 Phase {N} が進行中です。

次のアクション:
- `/design-docs:start` で続きから再開
- 特定のタスクを「完了」にマークしたい場合は「タスク {N}-{M} を完了」と指示
- Phase の状態を手動更新したい場合は指示してください
```

### すべて完了の場合
```
🎉 すべての Phase が完了しています!

次のアクション:
- 最終動作確認
- `/design-docs:plan` で次の機能の設計書を作成
- `/design-docs:switch` で別の設計書に切り替え
```

---

## ステップ4: 進捗の手動更新（ユーザー指示時）

ユーザーが以下のような指示をした場合、`tasks.md` を更新する:

### 「Phase X を完了」
- 該当 Phase のすべてのチェックボックスを `[x]` に更新
- 進捗記録テーブルの Status を ✅ Done に更新
- 完了日を今日の日付 (`date +%Y-%m-%d`) で記入

### 「Phase X を着手」
- 進捗記録テーブルの Status を 🚧 In Progress に更新

### 「タスク X-Y を完了」
- Phase X の Y 番目のタスクのチェックボックスを `[x]` に更新

### 「Phase X をブロック」
- Status を ⏸️ Blocked に更新
- ブロック理由をユーザーに聞いてメモ欄に記録

---

## ステップ5: 進捗レポート出力（オプション）

ユーザーが「レポート」と指示した場合、以下の形式で詳細レポートを表示:

```
📊 進捗レポート

📁 設計書: {パス}
🗓️ 作成日: {YYYY-MM-DD}
📅 現在日付: {YYYY-MM-DD}
⏱️ 経過日数: {N} 日

## サマリ
- 総タスク数: {N}
- 完了タスク: {N} ({XX}%)
- 残タスク: {N}

## Phase 詳細

### ✅ Phase 1: {名前}
- 完了日: {YYYY-MM-DD}
- タスク: 3/3 完了

### 🚧 Phase 2: {名前}
- 進捗: 2/4
- 残り: 
  - [ ] タスク A
  - [ ] タスク B

### 🔲 Phase 3: {名前}
- 未着手

## 次のマイルストーン
- Phase 2 の完了（残 2 タスク）
```

---

## 重要な原則

1. **進捗の信頼性**: tasks.md を常に最新の実態と一致させる
2. **自動更新は控えめに**: 明示的に指示されたタスクのみ更新する
3. **見やすさ優先**: 長い報告より、ステータスが一目でわかる形式を優先
4. **アクション提案**: 進捗を見せるだけでなく、次に何をすべきかを示す
