# AI駆動開発: 実装開始

カレント設計書に従って実装を開始します。

## ステップ1: カレント設計書の取得

`.claude/.current-design-doc` を読み、現在の設計書ディレクトリパスを取得する。

**ファイルが存在しない場合**:
```
❌ カレント設計書が見つかりません。

次のいずれかを実行してください:
- `/design-docs:plan` で新しい設計書を作成
- `/design-docs:switch` で既存の設計書に切り替え
```

---

## ステップ2: 設計書の読み込み

カレント設計書ディレクトリから以下を読む:
1. `requirements.md` — 要件・成功基準の確認
2. `design.md` — 実装方針・コード例の確認
3. `tasks.md` — 進捗確認と次のタスク特定

---

## ステップ3: 進捗確認

`tasks.md` の「進捗記録」テーブルを確認し、次に実行すべき Phase を特定する:

- すべて 🔲 Pending → Phase 1 から開始
- 一部 ✅ Done → 次の 🔲 Pending Phase から再開
- 途中 🚧 In Progress → その Phase の残タスクから再開
- すべて ✅ Done → 完了を報告

---

## ステップ4: 実装前の最終確認

次に実施する Phase の内容をユーザーに表示:

```
📋 カレント設計書: {パス}

次に実装する Phase:
  Phase {N}: {Phase 名}

タスク:
  - [ ] {タスク 1}
  - [ ] {タスク 2}
  - [ ] {タスク 3}

関連する design.md のセクション:
  - {該当セクション名と概要}

実装を開始しますか? (yes / 別の Phase を指定 / やめる)
```

ユーザーの承認を待つ。

---

## ステップ5: 実装

### 実装時の原則

1. **設計書を正とする**: design.md に書かれたコード例・ファイル配置・データフローに従う
2. **既存規約を遵守**: CLAUDE.md, `.claude/rules/*.md` のルールを守る
3. **小さくコミット可能な単位で進める**: 1 タスクずつ完了を目指す
4. **不明点は質問**: 設計書に曖昧な点があれば実装前に確認する
5. **設計書からの逸脱は報告**: やむを得ず変更する場合はユーザーに説明してから進める

### Phase ごとのタスクを順番に実装

- 各タスクに着手する前に、タスクの内容と関連コードをユーザーに示す
- 実装後、型チェック (`pnpm type-check`) を実行
- エラーがあれば修正
- エラーがなければ次のタスクへ

---

## ステップ6: Phase 完了時の処理

Phase のすべてのタスクが完了したら:

1. `tasks.md` の該当 Phase のチェックボックスを ✅ に更新
2. 進捗記録テーブルの Status を ✅ Done に更新、完了日を記入
3. ユーザーに報告:

```
✅ Phase {N}: {Phase 名} を完了しました

実装内容:
- {変更・追加したファイル一覧}

動作確認:
- [x] pnpm type-check 通過
- [ ] (必要なら) ブラウザで表示確認

次の Phase を続けますか? (yes / あとで / 別の Phase)
```

ユーザーの指示を待つ。

---

## ステップ7: 全 Phase 完了時

すべての Phase が ✅ になったら:

1. requirements.md の Success Criteria を一つずつ確認
2. 完了報告:

```
🎉 設計書のすべての Phase が完了しました!

📁 設計書: {パス}

実装した内容:
- {主要な変更・追加}

Success Criteria:
- [x] ...
- [x] ...

最終確認:
- [ ] 全体の動作確認
- [ ] 既存機能の回帰確認
- [ ] コミット作成

お疲れ様でした!
```

---

## 重要な原則

1. **設計書との一貫性**: design.md と異なる実装をしない。変更が必要なら設計書も更新
2. **Phase の独立性**: 各 Phase は独立して完了できる単位。途中で他の Phase に手を出さない
3. **進捗の可視化**: tasks.md を常に最新に保つ。口頭で「できた」と言うだけで終わらせない
4. **既存コードの尊重**: 設計書の「既存との関係」セクションに従う
5. **型チェック必須**: Phase 完了時には必ず `pnpm type-check` を通す
